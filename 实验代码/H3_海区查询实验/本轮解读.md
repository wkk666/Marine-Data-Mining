# 本轮小验证的解读

数据全部模拟：10,000 个随机船位点，加上 32 个专门检查边界的点；海区是一片有凹口的简化多边形。运行记录为 `runs/20261110_205508_135429`。完整表格见 [结果速览](结果速览.md)，运行和数据规则见 [README](README.md)。

四个方案最终选中的记录 ID 集合完全一致，都是 2,102 条。各方案误选 0、漏选 0，无重复 ID。8 个边中点和 8 个顶点均纳入，8 个内侧近邻纳入，8 个外侧近邻排除。覆盖格并集覆盖整片海区，扩大矩形枚举也没有发现遗漏相交格。

只查一次时，直接几何查询的“准备加首查”中位数为 0.2163 毫秒，低于 H3 三档的 5.1348、6.8924、15.9617 毫秒。这时建立索引、准备覆盖清单的费用占主导。直接对照已使用外包矩形初筛、几何预处理和向量化精判。

准备完成后，r7 的查询中位数为 0.0876 毫秒，是本轮最快的；直接方法为 0.1643 毫秒。r8 虽将需要精判的点减少到 485 个、精判时间降到 0.0235 毫秒，但查格与收集候选记录耗时为 0.1208 毫秒，最终查询为 0.1483 毫秒。减少精判点数量并不自动等于减少总耗时。r6 与 r8 的查询中位数相近，不据此细小差异判定普遍优劣。

准备阶段，r6、r7 主要花在点编码和分组；r8 的格子轮廓构造与分类达到 9.1531 毫秒，超过点索引的 5.6477 毫秒。详细准备分项和每次原始记录都已保存。

按“额外准备成本 ÷ 每次查询节省时间”用本轮中位数粗估，r7 需要约 90 次复用查询才可能抵消相对直接方法的额外准备成本。这只是摊销估算，不是实测累计 90 次的结论；条件是数据、海区及其索引可复用，且每次重算结果，双方都不缓存最终答案。

后续讨论应同时考虑查格/取记录、边界精判与准备成本的复用次数。本轮尚未设计或验证选择规则；也不能把 r7 在这片模拟海区和这一 Python 实现上的优势推广到所有海区或真实 AIS。
