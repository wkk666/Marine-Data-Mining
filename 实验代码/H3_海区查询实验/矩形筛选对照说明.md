# H3边界候选矩形筛选：单因素对照

本轮只检查实现因素。原版代码、上一轮探索数据与结果全部保留，不生成新数据、不调整分布、不实现选择器。

## 已核实的原实现

`run_experiment.py` 的直接查询先做包含边界的外包矩形筛选，再精判。原H3查询取得边界格点后，直接把全部边界候选交给同一几何谓词，没有显式矩形筛选。

根据保存的 `runs/explore_20261110_221236_751069/datasets/boundary_A` 重新核对，r7共有8,198个边界候选，其中2,965个在海区外包矩形外，筛后应精判5,233个点。本轮也会把重新编码结果与上一轮保存的逐条编码交叉核对。

## 唯一功能变化

新增函数 `bbox_ablation.query_h3_bbox` 保持内部格直接纳入逻辑不变，在边界候选的行号和经纬度收集完成后，增加：

```text
xmin <= 经度 <= xmax，并且 ymin <= 纬度 <= ymax
```

同时筛选行号、经度、纬度三个数组，再执行原精判。外包矩形边界计入，海区精判边界规则不变。r6、r7、r8采用同样的步骤。没有预先缓存筛好的候选行号。

## 主实验

比较7方案：直接查询，r6/r7/r8原版及各自加矩形版。原版直接调用未修改的 `run_experiment.query`。两种H3变体都调用原来的准备流程，各试次独立重新建立索引与覆盖清单。

K只取1000。每个“数据×方案”重复7次，同一轮随机交错28种组合。外层计时器从准备前到第1000次查询返回后停止。新增的矩形mask、坐标提取、三数组筛选和结果构造全部计入整体时间。各次查询仍重新构造返回结果，不缓存最终答案。

主实验的新函数不启用矩形步骤的专用计时探针；保留与原查询相同的核心总时间/精判时间边界，避免把额外分项计时作为主要性能差异。结果汇总以主实验总耗时中位数排名，并保存第25–75百分位与最小—最大。

## 单独分项诊断

主实验之后，另对同样7方案随机交错测31次准备后的单次查询。只在这轮诊断启用新版的mask和数组筛选专用计时，分别记录矩形条件、三数组紧凑化、精判、原始候选收集、结果构造等费用。

新增矩形筛选费包括mask和三数组整理。原本就需要的经纬度提取也始终在查询内计时。诊断结果只解释分项，不取代整体排名；不把分项中位数相加或乘1000当作主实验结果。

诊断CSV中直接方法的 `bbox_filter_ns=0` 仅表示没有新增H3边界过滤步骤；直接方法原有的矩形筛选仍计入其 `lookup_and_gather_ns`。

## 正确性和数据保留

直接精判参照以已保存经纬度计算完整ID集合。全部7方案应误选、漏选、重复均为0；原32个边界测试点保持纳入规则。预检和每个完整试次后的ID集合比较在计时之外，计时期间输入数组只读。测试另确认查询被调用K次且返回数组每次重新构造。

输入CSV和海区GeoJSON逐字节复制到新运行的 `input_data/`，来源与SHA-256保存到 `input_manifest.json`。全部旧运行和原有根目录文件在运行前记录指纹，结束后核对不变。新增运行目录名为 `runs/bbox_时间戳/`，使用独立的 `LATEST_BBOX_ABLATION.txt` 指针。
