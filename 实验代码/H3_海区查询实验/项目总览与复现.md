# 固定海区船位查询中 H3 分辨率的成本权衡与轻量选择方法评估

**报告以已确认的[Word和PDF定稿](../../实验报告/)为准。最终结论以 `runs/validation_20261111_151150_257869/` 的独立验证为依据。** [旧README](README.md)保留第一轮最小实验说明。

公开仓库为 [Marine-Data-Mining](https://github.com/wkk666/Marine-Data-Mining)。阅读入口见[仓库首页](../../README.md)，材料状态见[提交材料清单](提交材料清单.md)。对话记录由本人另行上传。

## 研究内容与已得到的结论

在同一片海区中，输入带唯一记录ID的经纬度点，返回归属于海区的记录ID集合，边界上的点计入。海区和全部船位记录均为模拟，不是真实AIS；记录数也不是唯一船舶数量。每组10,000条随机记录加32条边界测试记录，采用当前局部经纬度平面几何模型。

课堂已有“格子粗筛、内部格直接纳入、边界格精判”的基础。本作业围绕这个任务增加了三项具体设计：将共同准备、方法准备、选择和查询放入同一成本口径；用200点、仅r7编码的样本比例近似预测多个候选方法；用共享二选一基准和严格新增门槛，分别检验抽样价值与增加r6/r8选项的价值。这些是任务中的工程设计与实验检验，不把过滤、矩形筛选、抽样或直线成本模型宣称为理论首创。报告第3.6节集中解释课程延伸。

**部分固定H3方法在本实验场景较快，但当前样本选择策略未稳定胜过K-only。** 四种固定方法与三种选择策略的正确性检查均通过。样本二选一、四选一均在16/18场景命中事后最优固定方法，K-only为14/18；命中只比较方法名称，既不计选择费用，也不按省时大小加权。因此命中更多不等于完整任务更快。18场景来自六组独立数据，三个K和七轮计时不增加独立数据数量。

样本二选一与四选一在全部18场景选择相同方法。**本验证集未触发新增档位，未验证其被选中后的收益。** 事后用准确比例替换样本比例也未改变本轮推荐，不能将损失主要归为抽样选错。结果限于这片模拟海区、固定规模、有限分布和冻结实现，不推出普遍加速或抽样选择普遍无效。

K=1、100、1000是实验要求底层查询重新执行的次数：任务内复用准备资产，每次正常构造结果，不缓存最终答案。它不是现实系统应反复计算相同答案的建议。报告的完整成本指冻结校准参数已经存在时的一次在线任务；离线校准费用另列，不代表项目从零建设的全部成本。

## 用途一：核对已有结果，不重算实验

可直接用文本编辑器或表格软件读取CSV/JSON。若需要自动核对，在**本实验项目根目录**（本文件所在目录）用普通Python执行：

```powershell
python verify_independent_validation.py
```

该入口仅使用Python标准库，默认只读并打印核对结果，不导入查询模块，不生成点、执行查询计时或重新拟合，也不写审计文件。它核对已保存结果、统计、选择轨迹、时序及指纹；不是重新执行一次几何正确性实验。

现有脚本将目标目录固定为 `validation_20261111_151150_257869`，**没有 `--run` 参数**。它还检查 `previous_files_sha256.json` 所列旧材料、根部冻结代码/协议、校准来源及快照。迁移时要保留这些文件的相对结构和原字节，只有几份最终CSV不能通过完整指纹核对；换行转换也可能改变指纹。若公开材料尚不齐全，应说明缺项，不修改旧指纹来掩盖差异。

不要为只读核对加 `--write-audit`：该选项会尝试新增审计文件。另一个已有脚本[汇总脚本](summarize_validation_findings.py)会写入结果要点文件，不属于默认只读入口。原阶段说明中的本机Python路径只是历史环境记录，当前核对无需Codex依赖缓存。

下表文件均位于固定的最终验证目录；由 `dataset,K,scheme` 或 `dataset,K,strategy,control` 定位场景。

这里指重跑“冻结→按六个种子生成→保存推荐→预检/预热→882次正式任务→统计与诊断”的完整验证流程，**不重新探索、校准或改变模型**。本轮只提供说明，没有执行下列命令。

实验依赖锁定为H3 4.5.0、Shapely 2.2.0、NumPy 2.3.5，见[requirements.txt](requirements.txt)。原运行使用Python 3.12.14、Windows 11；建议先准备兼容的Python 3.12环境。普通解释器即可，不要求Codex缓存路径。在项目根目录的Windows PowerShell中：

模型SHA-256为 `f128d8595195128ae0d6f8f786fe77fb6951971b26c3e4de2841134aa7d1d096`。协议固定六种子3101/3102、3201/3202、3301/3302，K=1/100/1000，每组合七次，样本200、种子73001和2%规则均不变。40%/80%表示边界带生成成分比例，背景均匀点也可能靠近边界；带宽0.002度，非全球固定米数。

入口按脚本所在位置寻找项目，**没有模型、输出或运行目录的命令行选项，也不提供 `--help` 帮助模式**；不要用附加参数探测是否会运行。它新建 `runs/validation_时间戳/`，保存新记录并更新 `LATEST_INDEPENDENT_VALIDATION.txt`，不覆盖本报告引用的原运行。运行需要文件写权限；耗时会随机器、负载和依赖实现变化，原环境详见[environment.json][environment]。相同冻结种子的重算仍是同样六组数据的复现，不是又一批独立验证；新耗时也不能直接替换报告数值。
